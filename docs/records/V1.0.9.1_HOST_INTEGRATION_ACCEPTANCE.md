This record covers the sandbox implementation/verification gate. Windows Codex Desktop live acceptance remains a separate gate and is listed explicitly below; this document does not claim that live-host gate has passed.

## Implemented behavior

### 1. Aggregate workspace snapshot hardening

- Workspace snapshot traversal now prunes the existing mandatory forbidden directory set whenever a forbidden name appears in **any relative path component**, including nested `.git`, `.codebuddy`, `.qoder`, and `.qoderwork`. Snapshot-only pruning also excludes nested `.codex`, `node_modules`, `.venv`, and `__pycache__` trees so aggregate workspaces do not copy host metadata or dependency/cache bulk.
- Traversal never enters those subtrees, which prevents nested repository metadata such as `.git/refs/codex/turn-diffs/...` from being copied into the temporary read-only snapshot.
- Snapshot source/copy `OSError` failures are wrapped as `WorkspaceSnapshotError` with `phase="workspace_snapshot"`, a bounded relative path, and the exception class only. Raw absolute host paths are not projected into the Agent panel.
- Existing `sensitive_path_matches()` semantics are unchanged for non-snapshot policy callers.

### 2. Unified Codex first-use installer

The existing `skills/tp-voyager-captain/install_codex_desktop.py` remains the single host installer and now converges:

1. Captain Skill files and machine-local binding state;
2. the sole `mcp_servers.tp_voyager` registration;
3. the skills-only `tp-voyager-observability` plugin source;
4. the user's personal plugin marketplace entry;
5. the TP-Voyager managed guidance block in global `$CODEX_HOME/AGENTS.md`.

The observability plugin still has no `.mcp.json` or `.app.json`, so it cannot start/register a duplicate TP-Voyager MCP server.

The personal marketplace entry uses `policy.installation=INSTALLED_BY_DEFAULT`. If a stable `codex` CLI is available (or supplied with `--codex-cli`), the installer uses the documented `codex plugin add ... --json` path and verifies the host state with `codex plugin list --json`. If the CLI is unavailable or cannot verify the install, the installer reports `plugin_installed=false` and `plugin_installation_pending=true` instead of claiming a verified host install; the local default-install marketplace remains the Desktop restart fallback.

`--check` is read-only. With a Codex CLI available it may query only `codex plugin list --json`; it never runs `plugin add`, launches a Crew, or dispatches a Task.

### 3. Global Codex routing guidance

- Managed markers:
  - `<!-- >>> TP-Voyager managed guidance >>> -->`
  - `<!-- <<< TP-Voyager managed guidance <<< -->`
- Existing user text outside the markers is preserved byte-for-byte except for necessary boundary newline normalization around the managed insertion/update.
- Malformed/duplicate TP-Voyager markers fail closed rather than overwriting the file.
- A non-empty `AGENTS.override.md` is detected and reported as shadowing normal global guidance; the installer does not edit the user's override.
- The managed guidance explicitly allows simple tasks to remain direct and forbids automatic dispatch, retry, silent Crew/model changes, scope widening, permission expansion, or approval bypass.

### 4. Agent panel UX / failure projection

The MCP Apps resource URI and tool contracts remain unchanged.

The panel now surfaces:

- labeled `Crew`, `Model`, and `Task` identity;
- humanized Starting / Running / Completed / Failed state labels while keeping the existing status dot/border semantics;
- a current-activity summary;
- Timeline expanded by default with safe execution phase information;
- meaningful Conversation empty-state text instead of generic `No data.`;
- safe failure summary with `Stage` and `Reason`, e.g. `Workspace snapshot` + `FileNotFoundError`, without raw exception messages or absolute paths.

Provider-visible assistant output remains the primary conversation data. Hidden/private chain-of-thought is not captured or claimed.
